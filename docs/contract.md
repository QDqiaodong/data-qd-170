# Bounded EPUB text archive v1

Document maintainers provide one ZIP EPUB with mimetype=application/epub+zip, META-INF/container.xml, one OPF rootfile, dc:title/dc:identifier, a manifest and a nonempty unique spine of XHTML items. This is a text-focused EPUB subset, not a complete EPUB conformance validator or rendering engine. The code preserves declared spine order, extracts namespace-aware body text, excludes script/style content, collapses whitespace and indexes chapter title/body using SQLite FTS5 unicode61. It stores book source SHA256 and chapter paths in an independent SQLite archive; queries do not reopen the EPUB. The fixture generator creates original two-chapter prose and deterministic ZIP metadata.

No extraction to disk or external resource fetching occurs. Paths must be canonical relative POSIX paths with no dot/dot-dot segments, absolute names, backslashes or remote manifest URLs. Duplicate/encrypted ZIP members, missing spine members, non-XHTML spine items, DTD/entity XML and unknown spine refs fail. Limits: 500 members, 20 MB expanded total, 2 MB per referenced member. XML parsing additionally rejects non-UTF-8 input. No DRM, OCR, CSS layout, cover rendering or EPUB navigation model is supported. Text joins XML text nodes with spaces, so inline-element typography may differ from rendered prose.

Search accepts a nonempty <=200-character query, tokenizes Unicode letters/digits and ANDs literal tokens; it does not accept raw FTS operators. Results follow spine position and include snippets, capped at 100 chapters. Requires SQLite built with FTS5; availability is tested. CLI builds a temporary archive and atomically hard-links it into a new target, refusing existing files and symlinks. Any extraction/import failure leaves an existing target unchanged. Synthetic sample: 2 chapters; query harbor returns Evening then Morning; blue returns Morning only; hidden script marker is not indexed.
